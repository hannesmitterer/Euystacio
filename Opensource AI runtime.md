How to check your GitHub Copilot credit / usage status
GitHub Copilot (the AI‑powered coding assistant) shows the remaining credits (for the trial) or subscription status in a few places:

Where to look	Steps
GitHub.com → Settings → Copilot	1. Log into GitHub.
2. Click your avatar → Settings.
3. In the left‑hand menu select Copilot.
4. The Plan & Billing section displays whether you’re on the free trial, a paid subscription, and the number of remaining trial credits (if applicable).
Visual Studio Code (VS Code) extension	1. Open VS Code.
2. Click the Copilot icon in the activity bar (or run Copilot: Open Copilot from the command palette).
3. The panel header shows “Free trial – X credits left” or “Pro subscription active”.
GitHub CLI (gh)	bash\n# Install the Copilot extension for gh if you haven’t already\n gh extension install github/copilot\n\n# Show your Copilot status\n gh copilot status\n
The command prints the current plan and remaining trial credits.
GitHub Marketplace billing page	1. Go to https://github.com/settings/billing.
2. Click Marketplace on the left.
3. Locate GitHub Copilot in the list; the row shows your plan (Free trial / Pro) and renewal date.
What the statuses mean
Status	Meaning
Free trial – X credits left	You’re still in the 30‑day (or credit‑based) trial. Credits are deducted each time Copilot suggests code.
Pro subscription active	You’re on a paid monthly/annual plan; credits are unlimited, so the UI will just show “Pro” with the next billing date.
Expired / No credits	The trial has ended and no paid subscription is attached. Copilot will stop providing suggestions until you upgrade.
Common issues & fixes
Issue	Fix
Credits not decreasing	Make sure you’re signed into the same GitHub account in VS Code or the CLI. If you have multiple accounts, Copilot may be using a different one.
Billing page shows “Pending”	Verify that your payment method is valid; GitHub may pause the subscription until the charge succeeds.
Unable to see Copilot settings	Only users with a Pro or Trial subscription can access the Copilot settings page. If you don’t see the option, you haven’t activated a trial/subscription yet.
CLI command returns “not authorized”	Run gh auth login again and ensure the token includes the read:user and repo scopes, then retry gh copilot status.
If you still can’t locate the credit information, contact GitHub Support through the Help → Contact us link in the billing section, providing your GitHub username and the issue description.

Deep‑dive into checking GitHub Copilot credit / usage status
Below is a step‑by‑step guide that covers every official surface (web UI, IDE extensions, CLI, API) and the supporting data you can extract (billing records, usage logs, audit events).

2.1.1 Pulling the credit count programmatically (VS Code API)
If you develop a VS Code extension and need to display credits, you can read the Copilot authentication token and query the private endpoint used by the UI:

ts


import * as vscode from 'vscode';
import fetch from 'node-fetch';

async function getCopilotCredits(): Promise<number | null> {
  const token = await vscode.authentication.getSession('github', ['read:user', 'repo']);
  if (!token) return null;

  const resp = await fetch('https://api.github.com/copilot/credits', {
    headers: { Authorization: `Bearer ${token.accessToken}` },
  });

  if (!resp.ok) return null;
  const data = await resp.json();   // { credits: number, plan: "trial" | "pro" }
  return data.credits;
}
NOTE: The endpoint is undocumented and may change; for production use rely on the official Billing API (see § 4).

5. Auditing & compliance
Corporate environments often require proof of AI‑assisted coding usage. GitHub supplies two audit‑trail mechanisms:

Source	What it records	How to retrieve
GitHub Enterprise Audit Log	Copilot suggestion accepted, credits consumed, plan changes.	In Enterprise admin console → Audit log → filter action:copilot_*.
Copilot Usage Export (beta)	CSV export of every suggestion (timestamp, repo, file, lines changed, credits used).	Settings → Copilot → Export usage data (requires admin:org scope).
These logs can be forwarded to SIEM systems (Splunk, Elastic) via the standard GitHub webhook audit_log event.

6. Troubleshooting checklist
Credits not updating
Verify you are logged into the same account across all surfaces (web, IDE, CLI).
Run gh copilot status to see the canonical source; if it shows correct credits but the IDE does not, restart the IDE and clear its auth cache (Ctrl+Shift+P → Copilot: Reset authentication).
“Trial expired” but still seeing credits
The UI may be showing cached data (up to 15 minutes). Force a refresh (Ctrl+R in the browser) or wait for the next background sync.
Billing page shows “No active subscription” while CLI says “Pro”
You might be on a GitHub Enterprise Cloud organization plan that overrides personal billing. Check gh copilot status --org <org> for the org‑level view.
API returns 404
The endpoint is only available for accounts that have ever activated Copilot. If you have never started a trial or paid plan, the endpoint will be hidden.
Quick one‑liner for scripts
bash


credits=$(gh copilot status --json | jq -r .credits_remaining)
echo "Copilot credits left: $credits"
This can be inserted into a pre‑commit hook to warn developers when the trial is close to exhaustion.

Bottom line:

The most authoritative source is the GitHub Billing API (/copilot/credits).
The web UI and IDE sidebars are convenient for day‑to‑day checks.
For automation, GitHub CLI + gh copilot status or a direct API call give you programmatic access*
Use the combination that best fits your workflow—manual monitoring for occasional users, or API‑driven dashboards for teams that need governance over AI‑generated code.*
